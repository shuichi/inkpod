inkpod / file format

Native document container / current contract

.inkpod
ファイルフォーマット

現在の文書を保存するだけでなく、その文書を成立させた初期状態・不変アセット・確定操作・履歴分岐・編集状態までを、検証可能な形で保持するネイティブ形式です。

形式上の性質：非破壊的な手続き正本

現行状態の可変ラスターだけを正本にせず、再構築に必要な意味データと履歴を保存します。通常保存・読込はともに、失敗やキャンセルで既存ファイルや使用中の文書を途中状態へ置き換えません。

01 / PRINCIPLE

手続き正本モデル

`.inkpod` は procedure-authoritative（手続き正本）です。編集後の画素配列だけでなく、文書の起点と確定した操作列を保存し、読込時に同じ規則で文書を再構築します。

GENS不変の初期文書とベース面
ASST内容で識別される不変データ
PROC確定操作と履歴制御イベント
META現在位置・分岐・ID・savepoint
EDIT文書単位の編集再開状態
CKPT任意。削除可能な復元高速化キャッシュ
→
検証済みの文書状態 現在の内容 + 履歴 + Undo/Redo + 編集状態
A

再現可能

同じ Genesis・Assets・Procedures と replay epoch から、同じ意味状態を得ます。

B

履歴を保持

現在位置だけでなく、分岐、非アクティブ branch、Undo/Redo に必要な参照を残します。

C

途中公開しない

保存も読込も全検証が成功してから一度だけ結果を公開します。

「非破壊」の定義と範囲

非破壊とは、文書の意味状態、保持対象の履歴、編集再開状態、既存保存先、使用中のCore状態を、保存・読込の失敗途中で変更しない性質を指します。旧versionの読込互換性や、表示専用cache・window配置の永続化はこの定義に含みません。

02 / SECTIONS

七つの既知セクション

五つの必須セクションが文書の意味を構成します。二つの既知セクションは任意で、意味を変えずに高速化またはメタデータ保持を担います。独立した HIST セクションはありません。

FourCC要否役割レコード
META必須・criticalUUID、replay 契約、現在 State、履歴 cursor、active branch、文書／Editor savepoint、各 ID の次値、件数、期待 digest。kind 1 を 1 件
GENS必須・criticalGenesis の文書アーカイブ、初期 State/Branch、SolidWhite または Asset の不変ベース面。kind 1 を 1 件
ASST必須・critical不変 asset の descriptor と、最大 4 MiB に分割した payload chunk。kind 1 / 2 を 0 件以上
PROC必須・criticalCommit、Undo/Redo/Jump、branch cut をファイル順に保持する append-only journal。kind 1 / 2 / 3 を 0 件以上
EDIT必須・criticalactive tool、tool 別の色・径、fill/selection/geometry 設定、active layer/plane、palette cursor。kind 1 を 1 件
CKPT任意検証に成功した場合だけ使う再生高速化キャッシュ。削除しても復元結果は不変。kind 1 を 1 件
EXTM任意・opaquereplay に影響しない拡張メタデータ。Core は内容を解釈せず保持。opaque record

未知の critical セクションは、意味を安全に解釈できないため拒否します。未知の任意セクションは opaque-preserve のときだけ受理し、再保存時に内容を byte-for-byte で保持します。

Cell と Cut は同じ拡張子でも別コンテナです

通常の Cell は INKPOD\0\0、Cut descriptor は INKCUT\0\0 の magic を持ちます。Cut は制作 metadata、将来作る Cell の既定値、最大64件の順序付き membership、独立した履歴と savepoint を保持し、各 Cell の画素・レイヤー・履歴を埋め込みません。Cut も version 27／runtime replay epoch 24／payload schema 2 だけを受理し、保存は descriptor 一ファイルだけを原子的に置換します。

03 / RECONSTRUCTION

読込と再構築

ファイルを開く処理は、使用中の文書を直接書き換えません。別の staged Core で構造・参照・digest・再生結果を確定し、成功した完成状態だけを置き換えます。

ヘッダーと directory を検証

magic、v27、container epoch 9、サイズ、整列、範囲重複、ゼロ予約領域、FileRootDigest を確認し、META と procedure の runtime replay epoch 24 も照合します。

セクションを検証

必須セクション、record schema、stored/logical digest、件数とリソース上限を確認します。

Genesis と Assets を構築

asset descriptor・chunk・AssetId を照合し、初期状態と参照可能な不変データを staged Core に用意します。

Journal を再生

有効な CKPT があれば接頭辞を厳密照合して利用し、不一致なら Genesis から全 PROC を再生します。

META と EDIT を照合

現在 State、branch、cursor、ID 次値、文書／Editor／journal digest、savepoint が再生結果と一致することを確認します。

一度だけ公開

すべて成功したときだけ staged Core を live Core と置き換えます。失敗時は使用中の文書を変更しません。

CKPT は正本ではありません

epoch・journal prefix・state・policy counter がすべて一致したときだけ使われます。意味上の不一致は全 replay へフォールバックし、壊れた framing・範囲・hash はファイル全体の拒否になります。

04 / HISTORY

永続履歴モデル

Genesis は StateId(1)／BranchId(1) から始まります。永続 ID は非ゼロで再利用されず、META は「次に割り当てる値」を保持します。

Commit

primitive、canonical arguments、asset/ID 参照、前後の State digest、payload digest を記録する確定編集です。

HistoryMove

Undo、Redo、Jump の source/destination State と移動後の active branch を記録します。

BranchCut

branch の途中から新しく編集したとき、fork State、旧 tail、新旧 branch を直後の Commit と対で記録します。

  • event ID はファイル順に 1 ずつ増えます。procedure ID と committed State ID も各 namespace で単調増加します。
  • Undo/Redo/Jump の no-op、意味上の編集 no-op、失敗、キャンセル、stale base、overflow は ID を消費せず record を追加しません。
  • 非アクティブ branch と redo tail から参照される asset も保持されるため、再保存後も branch の再生が成立します。
  • 通常保存は履歴を自動 squash しません。
履歴を落とす操作は「明示的 compaction」のみ

compaction は省略される event/procedure 数と digest を含む最新の確認 token を要求し、現在文書を新しい Genesis とする別ファイルを書き出します。live 文書の path、journal、savepoint、dirty、ID は変更しません。

05 / PRIMITIVE CATALOG

Coreの現行Primitive catalog

文書を変更する確定操作は、PROCのkind-1 CommitにPrimitive呼び出しとして記録されます。ファイルの再構築にはこの呼び出し列に加え、GENS、ASST、履歴制御event、META、EDITが必要です。

01 / Commit

PrimitiveId、schema、epoch、前後のState digest、canonical引数、asset／stable-ID参照、payloadを保持します。

02 / Catalog gate

headerのcatalog digestが、ID・schema・名前・意味revision・work式・replay方針を含む現行カタログと一致する必要があります。

03 / Replay

typed decoderが全byteを消費し、同一canonical bytesへ再encodeできたjournal-replayable呼び出しだけをlive編集と同じexecutorで実行します。

PROCのすべてがPrimitiveではありません

kind 1のCommitだけがPrimitive実行です。kind 2のHistoryMoveとkind 3のBranchCutは履歴制御eventです。query、view、transient preview、ingestion、export、application command IDはPrimitiveIdではありません。76件のcatalog entryのうちLightTableSwapWithActiveはsession-levelのGenesis置換であり、Commitには出現しません。

06 / INTEGRITY

完全性とcanonical表現

すべての意味 digest と container digest は BLAKE3-256 の derive-key mode を使い、用途別の context で domain separation されます。これは改変・破損検出であり、暗号化や署名ではありません。

検証対象digest が保証する範囲
File rootroot 欄だけをゼロ化した 128-byte header と、directory 全体。
SectionFourCC・schema・compression と、格納 bytes／論理 bytes。二つを別 context で検証。
Document state文書 metadata commitment と、Plane ID 順の raster commitment。tile 単位で階層化。
Journal prefixevent 1 から指定件数までの PROC record bytes と順序。
Asset / chunkcanonical descriptor と logical payload、および 4 MiB chunk の identity・位置・bytes。
Procedure payload非空 inline payload の canonical bytes。
Editor state12-field の canonical EditorState。revision と savepoint 自体は digest 外。

canonical 表現

  • 整数はすべて little-endian の固定幅。boolean は u8 の 0 または 1 だけです。
  • 文書座標は小数部 16 bit の signed Q16。浮動小数入力は nearest／ties-to-even で正規化します。
  • 色は straight-alpha sRGB の RGBA8 または RGBA16 をタグ付きで保持し、RGBA16 を 8 bit に量子化しません。
  • sequence は意味順を維持し、set/map は canonical bytes 順。予約 bit/byte と padding はゼロです。
  • NaN、infinity、非 canonical な別表現、未知 code、余分な trailing bytes は拒否します。

Rangesheader、directory、section 同士は重ならず、total length を越えない。ファイル拒否
Padding領域間の全 gap byte は 0。ファイル拒否
EOFdirectory end が total file length と一致。trailing bytes は存在しない。ファイル拒否
Compression現行 reader は code 0（None）のみ。stored length = logical length。非対応として拒否
08 / ASSETS

Content-addressed asset

AssetIdは32-byteのAssetDigestです。同じcanonical descriptorとlogical payloadからは、取り込み元やcodecにかかわらず同じAssetIdが得られ、同一assetとして重複排除されます。

01

CanonicalRaster

BinaryMask8、Grayscale8/16、straight RGBA8/16。row padding なしの top-to-bottom bytes。

02

CanonicalGeometryStream

順序と Q16 数値規則を含む canonical geometry sequence。

03

CanonicalSampleStream

大きな stroke sample payload など、primitive schema が定める canonical sequence。

  • storage 上は 4 MiB 境界で決定的に chunk 化しますが、chunk 分割は AssetId を変えません。
  • descriptor、logical length、element count、stride、chunk 順序と digest を照合してから公開します。
  • encoded source bytes、ファイル名、path、timestamp、provenance は AssetDigest に入りません。
  • Genesis、全 retained branch／redo tail、既知の永続参照が asset retention root です。
09 / ATOMICITY

Atomic saveとstaged open

非破壊性は container の中身だけでなく、I/O の commit 境界にも適用されます。

通常保存

  1. section layout と digest を先に確定
  2. 同じ directory に排他的 temporary file を作成
  3. 1 MiB ごとに cancellation を確認しながら stream 書込
  4. flush → sync_all → close
  5. 同一 volume で destination を replace
  6. 成功後にだけ path と document/editor savepoint を公開

失敗・キャンセル

  • 既存 destination を変更しない
  • この保存用の temporary file だけを除去
  • path と savepoint を進めない
  • Core の文書・revision・dirty・history を変更しない

recovery の分離

recovery save も同じ atomic replacement を使いますが、通常 savepoint や通常 path を更新しません。recovery open は dirty・pathless として開くため、その後の通常保存が元ファイルを暗黙に上書きすることはありません。

10 / SCOPE

意味状態の永続化範囲

フォーマットは「同じ編集文書を再開するための意味」を保存します。表示装置や runtime 実装に依存する状態は切り離します。

正本として保存

  • UUID、paper、DPI、sRGB、frame、margin、base surface
  • layer/plane tree、stable IDs、可視性、編集可否、opacity
  • Text／Instruction annotation、角度付き撮影frame、消失点object
  • raster tile、selection mask、adjustment
  • palette、main-line color、guide、grid、Light Table
  • project/cut/cell/frame/sequence identity と animation metadata
  • journal、履歴分岐、cursor、Undo/Redo、ID high-watermark
  • EditorState と document/editor savepoint

意味上の正本から除外

  • current materialized documentとcheckpoint archive（cacheとして保存される場合がある）
  • inverse delta、COW snapshot、render/GPU/tile cache
  • zoom、pan、view flip、monitor、OS DPI、antialiasing
  • session-localなDocumentRevision（open時に1へrebase）
  • 外部sourceのpath、ファイル名、timestamp、encoded codec bytes
  • source UUID/revision/DPIなどreplayに不要なprovenance

除外対象のうちview・runtime cache・DocumentRevisionはnative文書へ永続化しません。任意provenanceを保持する場合は、replayの意味へ混ぜずEXTMなどのopaque metadataとして扱います。checkpoint内のmaterialized archiveは保存される場合がありますが、Genesis・Assets・PROCの代わりにはなりません。

12 / COMPATIBILITY

Versionと互換方針

現行 reader/writer が受理する native contract は、top-level version 27／runtime replay epoch 24／現在の primitive catalog の組み合わせだけです。

VERSION

v27 only

v27 以外は payload decode や live Core の置換前に拒否します。

SEMANTICS

epoch 24

replay 結果を変える規則変更は epoch と top-level version を同時に更新します。

COMPRESSION

None

現在受理する compression code は 0 のみです。

後方互換性は未提供

フォーマットフリーズが明示されるまでは current-only です。旧版 reader、migration、compatibility shim はありません。この制約は、同一 v27 ファイル内の意味データを非破壊に保持する設計とは別の軸です。

13 / VERIFICATION

非破壊性の検証契約

現行実装におけるIO-001の状態はVerifiedです。非破壊性の検証対象は、単純な再openに加えて以下の契約を含みます。

✓
意味状態の round-trip

保存前後で DocumentStateDigest と canonical composite を比較し、RGBA16 を含む全 pixel format が無量子化で一致すること。

✓
履歴 authority の round-trip

journal record、cursor、active/non-active branch、Undo/Redo、両 savepoint、すべての next-ID authority が一致すること。

✓
checkpoint 非依存

CKPT あり、CKPT 削除、意味上の mismatch から full replay の三経路が同じ結果になること。壊れた CKPT は拒否されること。

✓
非アクティブ branch の asset 保持

現在状態から見えない branch／redo tail の asset も再オープン後に replay できること。

✓
atomic save

encode、write、flush、cancel、replace の失敗時に既存 bytes、path、savepoint、dirty、history が変化しないこと。

✓
staged open

破損・過大・旧版ファイルの open 失敗後も、使用中の Core 文書と通常ファイルが完全に不変であること。

✓
opaque extension の round-trip

未知の optional/opaque-preserve section が Core 経由の再保存後も同一 payload を保つこと。

✓
compaction の隔離

stale token を拒否し、成功時も別 copy だけが新 Genesis となり、live authority を変更しないこと。
