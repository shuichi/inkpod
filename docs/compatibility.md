# Compatibility status

This is the single record of implementation status, known gaps and representative
verification for the requirement IDs in [SPEC.md](../SPEC.md). Detailed behavior
belongs to SPEC; ownership to [architecture.md](architecture.md), exact bytes to
[file-format.md](file-format.md), and test procedures to [verification.md](verification.md).

Status is `Not started`, `In progress`, `Experimental`, `Verified`, or `Blocked`.
`Verified` requires tests of the requirement's observable result at its production
UI boundary, or its natural Core/ABI/build boundary for infrastructure. It does
not imply verification on every platform or physical device. Historical version
numbers in evidence describe that test run, not an accepted legacy format.
Current version authority is SPEC section 20 and the exact header/codec contracts.

## Cross-cutting limits

- Common-raster PNG/TIFF codec and pair contracts retain 16-bit pixels, but current
  full product normal-pair Save/reopen evidence for both 16-bit formats remains pending.
- Pair save is one logical transaction with bounded journal/backup recovery, not an
  atomic replacement of two filesystem objects. Unresolved journal/cleanup evidence
  keeps a destination busy. A nonparticipating process may still race the final
  alias scan; portable non-Windows replacement retains its documented narrow ABA window.
- Namespace-observer-backed inventory reuse is Windows-only. Other backends
  re-enumerate; a future sandboxed frontend still needs a file-authority adapter.
- Shared image I/O does not cover GUI icons, palette/chart, shortcut/settings,
  clipboard memory images or test fixtures. Native compression accepts code 0 only.
- `revision-max` retains the scalar-aliasing and transparent-recomposition limits
  explicitly accepted in SPEC. These are not silently replaced by a stronger cache key.
- Physical high contrast, 200% DPI, screen-reader, IME and pen/touch coverage must
  be recorded independently. Reference Check AutoHide remains unreachable by F6/Tab.
- InkScript has private Rust/ABI/application smoke routes but no product file
  filter, command, pane or clipboard route. Full performance/cutover gates remain
  pending; independent `.inkbatch` v5 is not an InkScript product acceptance result.
