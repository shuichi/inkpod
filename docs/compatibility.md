# Compatibility status

This document tracks only the current status, representative evidence, and
known difference for every requirement ID defined in
[`../SPEC.md`](../SPEC.md). Detailed behavior belongs to `SPEC.md`, ownership
and data flow to [`architecture.md`](architecture.md), exact format bytes to
[`file-format.md`](file-format.md), and current platform verification to
[`implementation-status.md`](implementation-status.md).

Status is one of `Not started`, `In progress`, `Experimental`, `Verified`, or
`Blocked`. A user-facing requirement is `Verified` only when its production UI
route and observable result are tested; infrastructure requirements may be
verified at their natural build, ABI, Core, format, or renderer boundary.
Older ABI/native/replay numbers inside a representative-evidence cell identify the
historical gate that first fixed that behavior; only rows explicitly labelled
exact-current/current-only define the present version contract.

The current Windows CI correction keeps the `SEQ-001` presentation fence
independent of document-revision monotonicity: pair-backed replacement waits for
one exact application completion and the selected UUID/presentation epoch, and
the resolver-proven clean target is re-registered as the pristine sequence
source after outgoing-cache invalidation. The `WORKSPACE-001` product probe now
removes the fixed Bottom Sequence height only while exercising its same-selected-
tab Color/Layer/Reference Structure transaction, then restores it. This makes
the probe valid on the small CI desktop without changing the production rule
that insufficient pane minimum height creates another tab. Current x64 Debug
English/Japanese product smokes pass. A later x64 Release sequence-performance
run also passes with all 128 measured switches in the foreground, zero warm
read/decode/upload work, one snapshot per switch and no change to the approved
workload or timing envelope.
