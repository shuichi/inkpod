differences, and latest representative verification. Requirement-by-requirement

| Editor-state ownership | M3 is implemented at the Core/ABI/Windows presentation boundary. Rust-owned immutable `EditorDefaults` provides the 1920 x 1080, 96-DPI built-in document spec and is copied into each new session; each Core document session then owns one typed `EditorState`, nonzero `EditorRevision`, domain-separated canonical digest, editor savepoint, and editor dirty state. Active/last color tool, per-tool exact RGBA8/RGBA16 color+alpha and Q16 diameter, fill/Light-Table, selection, vector options, stable active layer/plane target, and palette cursor have one Core owner. Palette content, main-line color, and selection mask remain document primitives. Same-document views share one EditorState; different sessions remain isolated. Topology changes, native open, sequence activation/step, and Light Table swap deterministically reconcile stable targets in the staged publish boundary. The four target-changing topology creators (`create_layer`, `create_plane`, selection-to-layer, and vector rasterize) also stage their stable-ID cursor and publish it only after EditorState reconciliation succeeds. Semantic no-op and invalid/stale/overflow/failure are atomic; a valid editor-only update changes editor revision/digest/dirty but not document revision, StateId, journal, Undo, document savepoint, or render content. Procedure entry copies exact color/diameter/options/target rather than consulting live EditorState later. C ABI v2 adds seven functions and seven fixed-layout records for defaults/state query, typed update, exact-depth stroke begin, and captured-target fill/selection/color-selection; Windows keeps only a session/generation/revision/digest-bound copied presentation cache and re-queries on document/view/workspace switches. Representative coverage is in Core `editor_state` public contracts and codec goldens, FFI defaults/state validation and captured-target contracts, sequence/Light Table reconciliation tests, plus Windows CoreHost/command-state/GUI ownership smoke. |
| Immutable Genesis and canonical assets | M4 is complete for its defined slice. Every document has distinct stable Document and Cell IDs and an immutable typed base surface: allocation-free opaque `SolidWhite` or a canonical `Asset` reference. The base participates in flat composite/export but is not an editable layer, layer-only export, or selection content. A Core-owned content-addressed registry validates bounded descriptors and payloads, derives `AssetId` from canonical descriptor-plus-payload bytes, deduplicates independently of path, codec, and import source, and retains no caller path or buffer lifetime. Genesis, every journal branch and inactive redo tail, persistent references, and active transient operations are retention roots; failure publishes neither partial registry entries nor document state, and session close releases that session's registry. Legacy raster-open/import, clipboard, and Light Table ingestion synchronously copies and interns on the Core owner thread. ABI v3 additionally exposes bounded runtime color/sample/raster registration with generation-tagged IDs; primitive canonicalization resolves those IDs before commit and leaves no runtime ID in the procedure. Stroke samples are copied into an inline payload through 4 MiB and promoted to a canonical sample asset above that cutoff; sequence remains a bounded Rust-owned raster copy and vector primitive wiring remains M6. Full replay first deep-copies rooted payloads into a detached empty registry and re-ingests them by expected identity, with no shared `AssetRecord`, payload, or raster ownership. The successor model is schema/domain 4 with replay epoch 5 and reserved top-level v7; production `.inkpod` remains exact-current v2, and `GENS`/`ASST` persistence remains M8. Final Core, FFI, Windows, and performance verification is recorded below. |

## Known differences

- M2 is complete for the canonical procedure slice established by M1; the
  procedure-authoritative successor as a whole remains partially implemented.
  The Core journal, branch graph, StateId savepoint, and cache-free replay apply
  while history consists of main-line color, palette replacement, and one
  raster-stroke procedure. Any remaining document route marks the
  journal incomplete and retains the runtime inverse/COW cache; it is not
  converted into a synthetic snapshot or diff procedure. ABI is v2, and
  `.inkpod` v2 still saves materialized state and resets runtime history on open.
  The implemented slice is not evidence for the later all-route, ABI, format,
  or cross-architecture cutovers.
- M3 Core/editor ownership is implemented, but production `.inkpod` remains
  exact-current v2 and omits the canonical EDIT record and editor savepoint.
  Normal v2 save cannot clear editor dirty, and reopen initializes built-in
  defaults instead of restoring the prior EditorState. This honest combined-
  dirty behavior remains until the atomic M8 format cutover; it is not evidence
  of end-to-end EditorState persistence.
- Runtime schema/domain 4 now commits a distinct Cell ID and immutable Genesis
  base, and replay epoch 5 reserves successor top-level v7. Production v2 has
  no `GENS`/`ASST` sections, so v2 open reconstructs a fresh distinct Cell ID
  with `SolidWhite` and cannot restore an Asset base, canonical registry, or
  retained branch asset graph until the atomic M8 container cutover.
- The M0 inventory records current Windows composition debts for hidden-layer
  and all-guide deletion loops, new-cell post-conversion, vectorize destination
  creation, converted-paste plane creation, and chart palette/editor updates.
  Their all-or-nothing Rust ownership remains M6 work; no new wrapper was added
  in M0.
- Normal user-initiated `.inkpod` save/open still waits synchronously for the
  Core-engine work item. Autosave and image-processing tasks use asynchronous
  queue/task paths.
- All sessions still share one `CoreHost` execution lane. Per-session latency,
  the native delay test, and the fixed G13 scenarios show that accepted input is
  retained without partial commit; current measurements do not justify relaxing
  the single-writer owner-thread model.
- The current Windows UI resource set is Japanese-only. English display-language
  fallback therefore remains Japanese and is recorded in the G13 release
  checklist instead of being represented as completed English localization.
- Vector layers preserve their mutual z-order, but the current snapshot renderer
  draws vector content after precomposited raster tiles instead of supporting
  arbitrary raster/vector interleaving.
- Batch output currently writes native `.inkpod` cells.
- Native v2 blobs are separated but not compressed; compression remains an
  optional future container feature.
- Administrator MSIX install/installed-ABI/uninstall smoke remains optional
  validation rather than an implementation gap.
