differences, and latest representative verification. Requirement-by-requirement

## Current implementation

| Area                   | Current state                                                                                                                                                                                                                                                                                                                                                                                                           |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Product surface        | The native Windows application connects the maintained drawing, fill, selection, layer/plane, transform, light-table, sequence, vector, filter/effect, adjustment, import/export, Batch, document-tab, split-editor, multi-window, locator, reference-viewer, workspace-preset, and recent-file operations from production commands through the C ABI to Rust Core. All 329 production commands are menu-accessible and have configurable displayed shortcuts.                                             |
| Rust Core              | `inkpod-core`, `inkpod-image`, and `inkpod-format` are OS-independent. Immediate document edits use one owning, stale-checked transaction for no-op detection and atomic document/revision/history/cache publication; specialized preview, cancellable, reload, and long-running paths retain their staging ownership and share its final publish boundary. Core-owned identities/revisions and private document/device coordinate, dimension, offset, rectangle, and zoom values use distinct internal types while the public Rust API, C ABI, and file DTOs retain their established fixed-width boundaries. One typed view transform owns flip/zoom/pan conversion; locator, snap, stroke/effect input, transform helpers, and snapshot geometry convert at explicit boundaries. Documents use sparse tiled rasters, copy-on-write snapshots/history, typed layer/plane rules, savepoint-aware Undo/Redo, and bounded aspect-preserving per-layer RGBA thumbnails. Paint and fill retain the selected generic-raster plane ID across preview, commit, and history instead of falling back to another layer's color plane. Crate roots and the vector, Batch codec, transform, and view module indices are small declaration/re-export indices; their implementation is split by responsibility, private-invariant unit tests remain colocated, and public Core workflows compile as a separate multi-module integration target. |
| Windows frontend       | UI/Input, Core engine, and Renderer are separate long-lived threads. `Application` owns startup/message-loop/shutdown, including exact quoted-Unicode command-line parsing and opening one shell-supplied document through the same native/raster and Recovery-aware path as the File menu. MainWindow owns message normalization and command routing, feature controllers own typed UI state, and pane/dialog modules use typed inputs/results without receiving the complete application state or Core. The canonical workspace is applied by a UI-thread `DockHost` from a bounded HWND-free model: full-width tool options, an 80-DIP left tool strip, central EditorArea, and a 320-DIP right color/layer stack remain the one-action Coloring default, while the four primary panes can use descriptor-constrained dock, tab/split, float, hide, and restore operations. A bounded HKCU version 4 record stores window/split/dock/pane placement and the selected or user-named preset without document paths; it migrates versions 2/3, rejects malformed records to defaults, and clamps windows to current monitor DPI/work areas. Coloring, Line Cleanup, Reference Check, Batch, and Focus presets plus save/save-as/restore/reset are production commands. Resource-titled standard-button edge strips make secondary-pane AutoHide pointer-, keyboard-, and screen-reader-accessible. Narrow/compact adaptation does not overwrite saved layout. Its 20 tool buttons use readable single-word Japanese labels rather than one-character abbreviations. Color-consuming commands keep independent current colors, initialize pencil to black and coloring commands to the coloring default, and synchronize the active value into the color editor on command changes. The color pane separately labels and previews the Core-owned main-line color and active coloring drawing color. Its software-antialiased hue ring is cached by size/DPI, the SV triangle by hue, and the opacity band by RGB; drag events use a color-only synchronization path instead of rebuilding all dock models. Resize invalidates both the pane's old layout and the size-dependent owner-drawn picker, so the HSV/opacity surface repaints without a tab switch. Font-metric-aligned HSV/hex/opacity values, RGBA fields, and the shared-command eyedropper remain connected. One composed swatch surface renders the main-line color as a hollow ring behind the alpha-aware filled drawing-color circle without sibling-window overlap. Mouse drag and keyboard updates preserve RGBA8/16 depth and alpha; a colorless eyedropper continues to update the preceding command's color. Committed fills synchronize the Core-selected standard coloring or generic raster plane across the plane palette and status, while zero-pixel no-ops retain the prior selection. Eraser options expose explicit `主線`/`彩色` targets synchronized with the active plane palette row, menu commands, and status. The diameter input uses a smaller DPI-scaled font and text-metric control height centered within the tool-options row. Layer and plane tiles expose selection, visibility/editability, actions, thumbnails/metadata, and drag reordering while sharing command state with menus. New-plane kind and storage format use standard text dropdowns in the owner-centered common modal; OK asks Core to validate the prospective plane and leaves the dialog open with an error for an invalid combination. Command routing and command-state catalogs cover every production command exactly once. |
| GUI modernization      | G0 through G11 are complete; G12 is next and has not started. G10 passed the x64 Debug/Release native gates and ARM64 Debug/Release fresh configure, strict cross-build, structural checks, package smoke, and MSIX assembly. On 2026-08-02 the user explicitly accepted that evidence as the G10 ARM64 gate on the AMD64 host; the nine ARM64 native executables remain accurately recorded as not run. G11 adds a UI-thread-owned, value-only `TabDragCoordinator` and Common Controls tab subclass. Issue-time workspace/group/session/view/generation tokens defer all placement changes until release, then route reorder, group/window move, Ctrl-copy/new-view, and tear-out through the same application model operations as menu, context-menu, and keyboard commands. Commit revalidates stale source/target, placement, active stroke, modal/effect state, and capture; cancellation, close, monitor/DPI/theme changes, or transfer failure preserve or restore exact view order, routing, Canvas binding, dirty, and history. Native tab-item drag images inherit the active Windows theme, DPI, and high-contrast rendering. A bounded UI-thread `WorkspaceWindowRegistry` owns up to eight heap-stable workspaces, current/last-focused selection, and persistence slots. Each window owns its top-level/child `HWND`, menu/status state, `DockHost`, `EditorArea`, panes, focus history, and layout, while `ApplicationHost` shares the document registry, one `CoreHost`, one `RendererHost`, clipboard, shortcuts, and jobs. Window close prompts only for dirty sessions whose final view is removed, preserves surviving windows and shared sessions, and only the final window starts shutdown. Each `DocumentSession` retains one Core binding; same-session views in one or more windows share document/history/dirty/savepoint while presentation state and one Canvas per visible editor group remain separate. |
| Rendering and input    | Canvas uses client device pixels with one typed document-to-device transform and no Core-side OS DPI scaling. Immutable snapshots move through a bounded ownership queue in session/view/Canvas/document-generation/surface-generation and document/view-revision envelopes. New pending frames replace only the older frame for the same surface; stale, hidden/occluded, queue-full, close, and shutdown paths release ownership without rerouting. Stroke/view-gesture payloads are Canvas-owned until the workspace takes a token plus surface generation; custom messages carry no C++ object pointer. The interaction-end notification carries only CanvasId and surface generation values and releases deferred workspace presentation for that exact surface. Every swap chain/target is renderer-thread-owned, while the D3D11/DXGI/Direct2D device graph is shared. Host-wide device loss rebuilds GPU state for all surfaces from retained snapshots without changing Core documents. Raster, vector, guide, and grid geometry remains in document coordinates. Raster hit quantization uses the same half-open pixel-cell rule as locator sampling and nearest-neighbor display, including magnified lower/right clicks, final-row/final-column clipping, and flipped views. |
| ABI                    | Public C ABI v2 exposes 167 versioned fixed-layout functions, including read-only prospective plane validation, atomic mixed-format sequence import, caller-owned size-query buffers for bounded layer/sequence thumbnails and locator neighborhoods, and Core-owner-thread subpalette view/apply/sample/snapshot functions. Header/export parity and a direct contract-test reference for every function are enforced. Opaque Core/snapshot/task ownership, copied/buffer-query records, panic containment, validation, and double-release behavior are covered at the boundary. |
| Persistence and codecs | `.inkpod` v2 uses bounded semantic `DOCM`, `LTBL`, `VECT`, and `ADJT` sections; `.inkbatch` is checksummed and versioned. Atomic save/recovery and PNG/TIFF/TGA/BMP import/export preserve supported depth, alpha, dimensions, and DPI. Before an explicit format freeze, application-owned formats accept only their exact current version and every serialized schema change increments the top-level format version. |
| Windows packaging      | CMake is the build entry point and drives the Rust static library, strict MSVC C++20 build, resources, tests, and unsigned x64/ARM64 MSIX assembly with architecture-matched app-local MSVC runtime payloads and `.inkpod` file-type registration. Unpackaged builds rely on the user's Windows **Open with** choice instead of modifying the registry.                                                                                   |
| Reliability            | Public readers reject bounded malformed dimensions, lengths, checksums, IDs, references, and unsupported layouts without partially replacing the current document or output. Deterministic mutation tests cover native, Batch, PNG, TIFF, TGA, and BMP readers; large sparse/COW and bounded dense-image paths plus sparse/dirty snapshots, view cache reuse, Undo/Redo, light table, vector, and Batch Core workflows have fixed-input benchmark coverage. |

## Known differences

- Normal user-initiated `.inkpod` save/open still waits synchronously for the
  Core-engine work item. Autosave and image-processing tasks use asynchronous
  queue/task paths.
- All sessions currently share one `CoreHost` execution lane, so a long-running
  operation in one session can delay work for another session.
- Vector layers preserve their mutual z-order, but the current snapshot renderer
  draws vector content after precomposited raster tiles instead of supporting
  arbitrary raster/vector interleaving.
- Batch output currently writes native `.inkpod` cells.
- Native v2 blobs are separated but not compressed; compression remains an
  optional future container feature.
- Administrator MSIX install/installed-ABI/uninstall smoke remains optional
  validation rather than an implementation gap.
- A future sandboxed frontend still needs byte/stream I/O and platform file-
  authority adapters; no Windows dependency is allowed in Rust domain crates.
