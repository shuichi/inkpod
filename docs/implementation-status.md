# Implementation status

This document is a compact snapshot of the current implementation, active
differences, and latest representative verification. Requirement-by-requirement
status and evidence live in [`compatibility.md`](compatibility.md); detailed
ownership and data-flow contracts live in [`architecture.md`](architecture.md).

## Current implementation

| Area                   | Current state                                                                                                                                                                                                                                                                                                                                                                                                           |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Product surface        | The native Windows application connects the maintained drawing, fill, selection, layer/plane, transform, light-table, sequence, vector, filter/effect, adjustment, import/export, Batch, document-tab, and recent-file operations from production commands through the C ABI to Rust Core. All 293 production commands are menu-accessible and have configurable displayed shortcuts.                                                              |
| Rust Core              | `inkpod-core`, `inkpod-image`, and `inkpod-format` are OS-independent. Immediate document edits use one owning, stale-checked transaction for no-op detection and atomic document/revision/history/cache publication; specialized preview, cancellable, reload, and long-running paths retain their staging ownership and share its final publish boundary. Core-owned identities/revisions and private document/device coordinate, dimension, offset, rectangle, and zoom values use distinct internal types while the public Rust API, C ABI, and file DTOs retain their established fixed-width boundaries. One typed view transform owns flip/zoom/pan conversion; locator, snap, stroke/effect input, transform helpers, and snapshot geometry convert at explicit boundaries. Documents use sparse tiled rasters, copy-on-write snapshots/history, typed layer/plane rules, savepoint-aware Undo/Redo, and bounded aspect-preserving per-layer RGBA thumbnails. Paint and fill retain the selected generic-raster plane ID across preview, commit, and history instead of falling back to another layer's color plane. Crate roots and the vector, Batch codec, transform, and view module indices are small declaration/re-export indices; their implementation is split by responsibility, private-invariant unit tests remain colocated, and public Core workflows compile as a separate multi-module integration target. |
| Windows frontend       | UI/Input, Core engine, and Renderer are separate long-lived threads. `Application` owns startup/message-loop/shutdown, including exact quoted-Unicode command-line parsing and opening one shell-supplied document through the same native/raster and Recovery-aware path as the File menu. MainWindow owns message normalization and command routing, feature controllers own typed UI state, and pane/dialog modules use typed inputs/results without receiving the complete application state or Core. The canonical workspace fixes full-width tool options above an 80-DIP left tool dock, Canvas in the center, and a 320-DIP right inspector with color/palette/chart above layer/plane. Its 20 tool buttons use readable single-word Japanese labels rather than one-character abbreviations. Color-consuming commands keep independent current colors, initialize pencil to black and coloring commands to the coloring default, and synchronize the active value into the color editor on command changes. The color pane separately labels and previews the Core-owned main-line color and active coloring drawing color. Its software-antialiased hue ring is cached by size/DPI, the SV triangle by hue, and the opacity band by RGB; drag events use a color-only synchronization path instead of rebuilding all dock models. Font-metric-aligned HSV/hex/opacity values, RGBA fields, and the shared-command eyedropper remain connected. One composed swatch surface renders the main-line color as a hollow ring behind the alpha-aware filled drawing-color circle without sibling-window overlap. Mouse drag and keyboard updates preserve RGBA8/16 depth and alpha; a colorless eyedropper continues to update the preceding command's color. Committed fills synchronize the Core-selected standard coloring or generic raster plane across the plane palette and status, while zero-pixel no-ops retain the prior selection. Eraser options expose explicit `主線`/`彩色` targets synchronized with the active plane palette row, menu commands, and status. The diameter input uses a smaller DPI-scaled font and text-metric control height centered within the tool-options row. Splitters, visibility, DPI-independent widths/ratios, session restore, explicit save/restore/reset, and left/right mirroring are connected. Layer and plane tiles expose selection, visibility/editability, actions, thumbnails/metadata, and drag reordering while sharing command state with menus. New-plane kind and storage format use standard text dropdowns in the owner-centered common modal; OK asks Core to validate the prospective plane and leaves the dialog open with an error for an invalid combination. Command routing and command-state catalogs cover every production command exactly once. |
| GUI modernization      | G0 through G5 are complete. The agreed multi-window, multi-document, split-editor, constrained-dock, pane-target, and session-lifecycle contracts plus the frozen pre-G1 baseline are tracked. The Windows frontend uses non-interchangeable strong workspace/session/view/group/Canvas/pane/job/generation IDs, one UI-thread target registry, issue-time pointer-free `CommandContext`, generation-bound async tokens, and stale-target rejection. Heap-owned `ApplicationHost` owns process services, one `CoreHost`, one `RendererHost`, and workspace/document registries; `WorkspaceWindow` owns top-level/child `HWND` and window presentation; each `DocumentSession` owns file/recovery identity and one non-owning Core binding; and each `DocumentView` owns Core view identity plus presentation state. The visible GUI now opens multiple document tabs in one window and editor group. Canonical volume/file or normalized-path identities prevent duplicate sessions, Save As rejects identity conflicts before writing, and successful saves update identity, title, recent files, and recovery metadata together. Tab activation transactionally rebinds the single group Canvas and active presentation; inactive-session completions validate captured session/generation and cannot retarget active pane/menu state. `CoreHost` still owns every `InkpodCore` on one owner thread and `RendererHost` owns all GPU state on one renderer thread. Split EditorGroups remain G6 work. The C ABI is unchanged. |
| Rendering and input    | Canvas uses client device pixels with one typed document-to-device transform and no Core-side OS DPI scaling. Immutable snapshots move through a bounded ownership queue in session/view/Canvas/document-generation/surface-generation and document/view-revision envelopes. New pending frames replace only the older frame for the same surface; stale, hidden/occluded, queue-full, close, and shutdown paths release ownership without rerouting. Stroke/view-gesture payloads are Canvas-owned until the workspace takes a token plus surface generation; custom messages carry no C++ object pointer. Every swap chain/target is renderer-thread-owned, while the D3D11/DXGI/Direct2D device graph is shared. Host-wide device loss rebuilds GPU state for all surfaces from retained snapshots without changing Core documents. Raster, vector, guide, and grid geometry remains in document coordinates. Raster hit quantization uses the same half-open pixel-cell rule as locator sampling and nearest-neighbor display, including magnified lower/right clicks, final-row/final-column clipping, and flipped views. |
| ABI                    | Public C ABI v2 exposes 161 versioned fixed-layout functions, including a read-only prospective plane validator and a caller-owned size-query buffer for bounded layer thumbnails. Header/export parity and a direct contract-test reference for every function are enforced. Opaque Core/snapshot/task ownership, copied/buffer-query records, panic containment, validation, and double-release behavior are covered at the boundary.                                                                                                      |
| Persistence and codecs | `.inkpod` v2 uses bounded semantic `DOCM`, `LTBL`, `VECT`, and `ADJT` sections; `.inkbatch` is checksummed and versioned. Atomic save/recovery and PNG/TIFF/TGA/BMP import/export preserve supported depth, alpha, dimensions, and DPI. Pre-v2 project files are intentionally unsupported.                                                                                                                             |
| Windows packaging      | CMake is the build entry point and drives the Rust static library, strict MSVC C++20 build, resources, tests, and unsigned x64/ARM64 MSIX assembly with architecture-matched app-local MSVC runtime payloads and `.inkpod` file-type registration. Unpackaged builds rely on the user's Windows **Open with** choice instead of modifying the registry.                                                                                   |
| Reliability            | Public readers reject bounded malformed dimensions, lengths, checksums, IDs, references, and unsupported layouts without partially replacing the current document or output. Deterministic mutation tests cover native, Batch, PNG, TIFF, TGA, and BMP readers; large sparse/COW and bounded dense-image paths plus sparse/dirty snapshots, view cache reuse, Undo/Redo, light table, vector, and Batch Core workflows have fixed-input benchmark coverage. |

## Known differences and unknowns

- Normal user-initiated `.inkpod` save/open still waits synchronously for the
  Core-engine work item. Autosave and image-processing tasks use asynchronous
  queue/task paths.
- All sessions currently share one `CoreHost` execution lane, so a long-running
  operation in one session can delay work for another session.
- Vector layers preserve their mutual z-order, but the current snapshot renderer
  draws vector content after precomposited raster tiles instead of supporting
  arbitrary raster/vector interleaving.
- Gap close, filters, effects, broadcast-color checks, and other algorithms whose
  proprietary legacy details are not independently specified use documented,
  deterministic Inkpod semantics. They are not claims of undocumented kernel
  compatibility.
- Batch output currently writes native `.inkpod` cells. The graph is extensible,
  but no undocumented legacy Batch or preset format is accepted or emitted.
- Native v2 blobs are separated but not compressed; compression remains an
  optional future container feature.
- DGA/CEL and legacy palette/chart/filter preset layouts remain `Unknown` with
  zero rights-cleared fixtures and zero measured read/write/round-trip variants.
- The generated MSIX is intentionally unsigned. Public distribution requires a
  protected production publisher credential and timestamp policy that must not
  be committed. Administrator install/installed-ABI/uninstall smoke remains
  optional release validation rather than an implementation gap.
- A future sandboxed frontend still needs byte/stream I/O and platform file-
  authority adapters; no Windows dependency is allowed in Rust domain crates.
