differences, and latest representative verification. Requirement-by-requirement
status and evidence live in [`compatibility.md`](compatibility.md); detailed
ownership and data-flow contracts live in [`architecture.md`](architecture.md).

Git history and are not duplicated here.

| Editor-state ownership | M3 is implemented at the Core/ABI/Windows presentation boundary. Rust-owned immutable `EditorDefaults` provides the 1920 x 1080, 96-DPI built-in document spec and is copied into each new session; each Core document session then owns one typed `EditorState`, nonzero `EditorRevision`, domain-separated canonical digest, editor savepoint, and editor dirty state. Active/last color tool, per-tool exact RGBA8/RGBA16 color+alpha and Q16 diameter, fill/Light-Table, selection, vector options, stable active layer/plane target, and palette cursor have one Core owner. Palette content, main-line color, and selection mask remain document primitives. Same-document views share one EditorState; different sessions remain isolated. Topology changes, native open, sequence activation/step, and Light Table swap deterministically reconcile stable targets in the staged publish boundary. The four target-changing topology creators (`create_layer`, `create_plane`, selection-to-layer, and vector rasterize) also stage their stable-ID cursor and publish it only after EditorState reconciliation succeeds. Semantic no-op and invalid/stale/overflow/failure are atomic; a valid editor-only update changes editor revision/digest/dirty but not document revision, StateId, journal, Undo, document savepoint, or render content. Procedure entry copies exact color/diameter/options/target rather than consulting live EditorState later. C ABI v2 adds seven functions and seven fixed-layout records for defaults/state query, typed update, exact-depth stroke begin, and captured-target fill/selection/color-selection; Windows keeps only a session/generation/revision/digest-bound copied presentation cache and re-queries on document/view/workspace switches. | Immutable Genesis and canonical assets | Every document has distinct stable Document and Cell IDs and an immutable typed `SolidWhite` or canonical `Asset` base. A Core-owned content-addressed registry validates bounded descriptors/payloads, deduplicates independently of path/codec, and roots Genesis, all journal branches/inactive redo tails, persistent references, and live transients. ABI v4 data-plane IDs are resolved before commit and never persist. V9 GENS/ASST streams the rooted asset graph in AssetId order with 4 MiB chunks and digest/identity revalidation; normal save, autosave/recovery, Batch output, checkpoint/full-replay reopen, compaction-copy write, and cache-free replay preserve the required asset authority. |

## Known differences

- Native `.inkpod` is current-only v9. All non-v9 files are deliberately rejected and
  have no migration reader before format freeze.
- `CKPT` is optional acceleration. Prefix/state/epoch mismatch performs full
  replay; malformed structure, hashes, or bounds reject without publication.
  The authoritative journal and retained asset graph are always preserved.
- The M0 Windows composition debts are closed in M6. Hidden-layer and all-guide
  deletion are single Rust operations; a new cell validates its requested layer
  kind in Genesis creation; target-zero vectorize, converted paste to a new
  plane, and chart palette replacement publish atomically. C++ stages only
  presentation state and delegates document meaning to Rust.
- Normal user-initiated `.inkpod` save/open still waits synchronously for the
  Core-engine work item. Autosave and image-processing tasks use asynchronous
  queue/task paths.
- All sessions still share one `CoreHost` execution lane. Per-session latency,
  the native delay test, and the fixed G13 scenarios show that accepted input is
  retained without partial commit; current measurements do not justify relaxing
  the single-writer owner-thread model.
- The current Windows UI resource set is Japanese-only. English display-language
  fallback therefore remains Japanese and is recorded in the G13 release
  checklist instead of being represented as completed English localization.
- Vector layers preserve their mutual z-order, but the current snapshot renderer
  draws vector content after precomposited raster tiles instead of supporting
  arbitrary raster/vector interleaving.
- Batch output currently writes native `.inkpod` cells.
- V9 sections use compression code 0 only. The checkpoint benchmark does not
  justify compression complexity; adding it changes the top-level format
  version and requires explicit decompression-work limits.
- Administrator MSIX install/installed-ABI/uninstall smoke remains optional
  validation rather than an implementation gap.
- A future sandboxed frontend still needs byte/stream I/O and platform file-
  authority adapters; no Windows dependency is allowed in Rust domain crates.
